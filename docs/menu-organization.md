# Logical menu organization

The Menu view arranges controls generated by Avatar Wardrobe into visual folders and an explicit order. Existing **Only one active** groups retain their switching behavior. Clothing objects, their transforms, generated control objects, control parameters, automatic-value settings, and default-control references are unchanged by organizer operations. Editing a layout marks the scene dirty and supports Unity Undo; it does not save the scene or rewrite preset settings.

The first supported roots are Wardrobe's generated `menu-groups` and `part-toggles` installers. Creator menus, menu assets, externally routed menus, and mixed generated/creator trees remain read-only with an Inspector handoff. A logical folder is a new parameterless submenu. Existing generated controls cannot be deleted or renamed through this surface. Moving a control changes only its presentation parent and insertion point. Removing a folder requires emptying it first.

`WardrobeMenuLayout` stores an ordered node list and references to the original Modular Avatar menu items. An existing root's `ModularAvatarMenuGroup.targetObject` or `ModularAvatarMenuItem.menuSource_otherObjectChildren` points to a small helper below the avatar. The helper's `MenuSource` visitor presents the original items in logical order. The original transform order remains unchanged, so Modular Avatar's automatic parameter-value assignment sees the original order. Folders invoke a parameterless submenu template; the adapter redirects submenu nodes without copying or changing parameters.

The helper implements `VRC.SDKBase.IEditorOnly`, so VRChat's editor-only stripping pass removes the component after menu processing. It adds no runtime avatar behavior. NDMF processing alone may leave SDK editor-only components until that stripping pass.

Menu regeneration calls `WardrobeMenuOrganization.Rebind` after recreating generated controls. Rebinding matches generated group ownership IDs and exact referenced scene targets. It preserves logical node identity and placement, appends newly generated controls, and removes references to deliberately removed controls. Children of a removed submenu return to the top of that menu. If a source root is deliberately removed, its dormant layout is retained in the scene for a later regeneration. Ambiguous ownership and newly introduced creator controls stop rebinding rather than silently dropping controls.

## Compatibility

This adapter is validated against **Unity 2022.3.22f1, Modular Avatar 1.18.7, and NDMF 1.14.8**. The MA dependency is pinned to `1.18.7` because MA describes `MenuSource`, `NodeContext`, and `VirtualControl` as an unstable public contract. Upgrading MA requires compiling and running the provider and NDMF output tests before changing that pin. No reflection or internal MA constructors are used by production code. A test-only fake constructs a virtual menu node to inspect visitor output.

The organizer accepts at most 128 installer roots, 512 nodes per layout, and 24 levels. Its commands require the pinned avatar ID, exact root instance ID, and a conservative revision of the avatar's serialized scene state. A stale revision, unsupported source, invalid parent, cycle, missing insertion point, duplicate folder name, or unsupported action fails without applying a partial layout. A failed browser request is never automatically replayed.

## Host integration

- GET `/api/menu_snapshot`: run `WardrobeMenuOrganization.Snapshot(SceneAvatar)` on Unity's main thread. Add this exact route to server and browser read allowlists.
- POST `/api/menu_execute?command=<URL-encoded JSON>`: deserialize `WardrobeMenuOrganization.CommandDto` and call `Execute`. Keep the normal pinned project/session/avatar request guards. The command is `{avatarId,rootId,revision,action,nodeId,parentId,beforeId,label}`. Actions are `initialize`, `folder`, `rename`, `move`, `deleteFolder`, and `inspect`. Empty `parentId` means menu root; empty `beforeId` means append.
- Snapshot: `{ok,avatarId,revision,message,roots}`. Each root has `{id,layoutId,name,path,editable,reason,nodes}`. Each node has `{id,parentId,label,kind,sourceId,isDefault,automaticValue,parameter,value}`. `kind` is `folder`, `switchingGroup`, `submenu`, `control`, or `readonly`. Source values are authoring values; MA resolves automatic values during building.
- Serve `/menu-organizer.js` from both Unity and desktop static allowlists. Add a Menu workspace element and call `WardrobeMenuOrganizer.configure({api,T,root}).show()`. `api` is the existing pinned-session adapter. `T` uses `menuOrganizer.*` keys with English fallbacks. Call `show()` when the Menu view is selected or its pinned avatar changes.
- The module reuses the `scene-editor` layout and form styles. Menu row and drop styles live in the shipped `Web/wardrobe.css`.

Validation covers read-only creator menus, exact source identity with duplicate target names, folder moves and Undo, invalid-command rollback, stale revisions, cycles and insertion points, regeneration rebinding, and a real NDMF build comparing control parameters and default values before and after organization.
